# GraphQLForum Modernization Plan

## Goal
Bring the 2020/21 stack to current, preserving behavior and URLs, fixing known bugs and the authorization holes along the way. `client/` and `server/` remain separate packages (no monorepo tooling churn).

## Locked decisions (per your answers)
- **Auth**: Keep Auth0, done properly — `@auth0/auth0-react` on the client, passport-jwt + jwks-rsa token verification on the server, identity derived from the token, author/admin guards on writes.
- **Editor**: Replace Froala with TipTap (open source, no license watermark).
- My defaults (flag if you disagree): keep MySQL 8 (dockerized for dev), NestJS 11 + @apollo/server 4 + graphql 16 + TypeORM 0.3, subscriptions via graphql-ws, Vite + React 19 + TypeScript 5 + Tailwind 4 + react-router v7 (library mode) + @apollo/client 3 on the client.

## Prerequisites (you, needed before final verification)
- Auth0 tenant: create an API (gives us the `audience` for token verification), add `http://localhost:5173` callback/logout URLs (Vite's port replaces CRA's 3000), and an Action that puts the `Administrator` role into a custom token claim (today that's done via the old `customPropertyNamespace` mechanism).
- MySQL: `docker compose` file is provided; can start fresh or point at your existing DB.

## Phase 0 — Foundations & hygiene
- Add `docker-compose.yml` (mysql:8 + volume), `server/.env.example` (`DB_*`, `AUTH0_DOMAIN`, `AUTH0_AUDIENCE`), `client/.env.example` (`VITE_GRAPHQL_ENDPOINT`, `VITE_AUTH0_*`).
- Delete dead code: `features/Login.tsx` (imported nowhere), `components/AnimatedSwitch.disabled` (react-pose), `junkyard/`, `common/directives/upper-case.directive.ts` (uses Apollo-2 `SchemaDirectiveVisitor`, gone in v4, never registered), debug `console.log('AJK …')` calls.
- Keep the logging plugin but port it to the @apollo/server 4 plugin API and actually register it (it's currently dead code).

## Phase 1 — Server framework modernization (contract-preserving)
- Upgrade: nest ^11, `@nestjs/graphql` (Apollo driver) + `@apollo/server` ^4, graphql 16, TypeORM 0.3 + mysql driver; drop `apollo-server*` and `graphql-tools`.
- `GraphQLModule.forRoot` with driver config, `subscriptions: { 'graphql-ws': true }`, logging plugin registered; `main.ts` gains env-driven port.
- TypeORM: replace `createConnection` + the five hand-rolled repository provider arrays + the `forwardRef` module web with `TypeOrmModule.forFeature(...)` (DataSource). This also removes the heavy provider duplication in `threads/module.ts` and `reply/module.ts`.
- Subscriptions: one shared `PubSub` provider (graphql-subscriptions) instead of four module-scope instances.
- **Bug fixes while the rest of the schema stays identical:**
  - `findLastReply` orders `when ASC, take(1)` — returns the *oldest* reply; fix to latest.
  - `userAdded` subscription listens on `userAdded` but `loginUser` publishes `userLoggedIn` — align topics (expose `userLoggedIn`, drop `userAdded`).
  - `updateReply` publishes topic `replyUpdated` under key `threadAdded` with no matching subscription — remove; keep `replyAdded` on create only.
  - Rename odd mutation args `DeleteThreadInput`/`DeleteReplyInput` → `data`.
  - Make `Thread.userLastReply` nullable in the schema (entity allows null for threads with no replies; currently a latent null crash).
  - Replace hardcoded `take(10)` with `PAGE_SIZE`.
  - Register a global `ValidationPipe` (all existing class-validator decorators are currently inert) and add missing validators to reply inputs.
- Tests: jest upgrade + `moduleNameMapper` for the `@server/*` alias (jest currently can't resolve it); replace the always-failing "Hello World" e2e with a GraphQL CRUD smoke test (skips without DB env).

## Phase 2 — Server auth & authorization
- New `AuthModule`: passport-jwt strategy verifying Auth0 access tokens via jwks-rsa; claims map to `{ sub, email, name, picture, roles }`.
- Guard policy: all mutations require auth; queries stay public (browsing without login still works).
- **Contract changes:**
  - Remove `user(code:)` and `loginUser`; add `me` query that upserts the user from verified claims (stored `code` = token `sub`, increments `logins`, sets `lastLogin` — preserves existing user rows).
  - Drop `authorId` from `NewThreadInput`/`NewReplyInput` — author comes from the token.
  - `updateThread`/`deleteThread`/`updateReply`/`deleteReply` return 403 unless caller is the author or has the `Administrator` role claim.
  - Stop exposing `code` (Auth0 sub) on the `User` type.
- Regenerate `schema.gql`; the delta list above is the input to Phase 3.

## Phase 3 — Client modernization
- **Tooling**: CRA → Vite (react plugin), TS 5, `REACT_APP_*` → `import.meta.env` `VITE_*`; delete the checked-in 63k-line generated `src/styles/tailwind.css`.
- **React 19**: `createRoot`; replace the unmaintained `react-modal` wrapper with a native `<dialog>`-based `Modal.tsx` (thin wrapper today).
- **Apollo 3**: `ApolloClient` + `InMemoryCache` + `authLink` attaching a Bearer token (`getAccessTokenSilently`); port the 13 refetch-based query/mutation call sites (mechanical — no cache-update logic to migrate).
- **Router v7**: `Switch`→`Routes`, split array-path route entries, 404 catch-all → `path="*"`, `useHistory`→`useNavigate` (7 sites); URL scheme unchanged (`/:forumId/:forumPage/:threadId/:threadPage`), so deep links keep working.
- **Auth0**: `Auth0Provider` (domain, clientId, audience); rewrite the 10 `react-use-auth` files — NavBar login/logout (keeping the save-location-and-return feature), callback pages via `handleRedirectCallback`, `IsAuthenticated`/`IsAdmin`/`IsAuthor`/`IsNotAuthenticated` from `useAuth0` + roles claim. `AuthContext` shrinks to redirect persistence; drop the localStorage `code` + `GET_USER`-by-code flow (and its render-phase `setState` anti-pattern); the `LoggedInCallbackPage` mutation becomes a `me` query after redirect.
- **Forms**: react-hook-form v7 (`{...register()}`, `formState.errors`, Controller `field` prop); move validation into register rules instead of the manual `onSubmit` checks.
- **Tailwind 4**: `@tailwindcss/vite`, port the custom palette from `tailwind.js` into `@theme`; fix renamed/dead classes (`grey-*`→`gray-*`, `shadow-xs`→`shadow-sm`, `whitespace-no-wrap`→`whitespace-nowrap`, `flex-shrink-0`→`shrink-0`) and the `focus:bg-red-700s` typo.
- **Editor**: reimplement `TextEditor.tsx` on TipTap (StarterKit + URL-based image insert; port the admin HTML source-view toggle as a simple toggle, or note it as dropped if fiddly); remove global Froala plugin/theme imports from `index.tsx`.
- Visual parity check page by page (home, forum, thread, modals).

## Phase 4 — Tests, CI, docs
- Client: vitest + testing-library — `timeAgo`, hooks, Modal, a form, one page render with mocked Apollo.
- Server: unit tests for services (create/update + authorization logic) and the GraphQL e2e smoke.
- GitHub Actions: server workflow (lint/build/test) and client workflow (lint/build/test).
- README rewrite: quickstart (docker compose, env, scripts), Auth0 tenant setup steps, architecture overview, and a list of intentional behavior/schema changes from this migration.

## Verification
Server boots and generated `schema.gql` reviewed; CRUD exercised via GraphQL; client walkthrough home → forum → thread with pagination; create/edit/delete as author, blocked as non-author, allowed as admin; login/logout round-trip preserves location; delete-last-reply page-move behavior intact; subscription smoke test over graphql-ws.

## Risks
- Auth0 tenant setup (API/audience, roles Action, new callback URLs) is on you; code can be developed against any tenant.
- Tailwind 1→4 is the likeliest source of visual regressions — mitigated by per-page comparison.
- `synchronize: true` stays for dev; production migrations are a documented follow-up.
- react-spinners/react-icons version bumps verified against React 19 during Phase 3.
